# 가성비 제품기획 리서치 자동화 (인수인계 문서)

이커머스(현재는 쿠팡) 생활용품 카테고리의 경쟁 제품을 조사해서,
**"가성비 포지셔닝으로 신제품을 내려면 어떤 규격을 얼마에, 생산원가 얼마로
만들어야 하는가"** 에 답하기 위한 도구 모음이다.

특정 회사 전용이 아니라, 제품기획을 할 때 공통적으로 반복되는 조사 작업을
코드로 만들어 둔 것이다. 그래서 결과물에 운영주체명은 넣지 않는다(아래 규칙 참고).

---

## 1. 먼저 읽을 문서 (중복 설명을 피하기 위한 지도)

이 문서는 **저장소 전체의 지도와 인수인계 사항**만 담는다.
도구 사용법과 설계 배경은 아래 문서에 이미 정리돼 있으니 그쪽을 보면 된다.

| 알고 싶은 것 | 볼 문서 |
|---|---|
| 명령어를 어떻게 치는지, 엑셀 컬럼을 어떻게 읽는지 | `thumbnail_analyzer/README.md` |
| 왜 그렇게 설계했는지, 무엇을 조심해야 하는지 | `thumbnail_analyzer/CLAUDE.md` |
| 저장소 전체 구성 / 현재 진행 상태 / 인수인계 | **이 문서** |
| 공장 전달용 견적요청서를 다시 만드는 법 | 이 문서 5장 |

`CLAUDE.md`는 Claude Code가 세션마다 자동으로 읽는 프로젝트 메모리다.
사람이 읽어도 되지만, **설계 판단의 근거**가 주 내용이다.

## 2. 전체 작업 흐름과 현재 상태

| 단계 | 하는 일 | 담당 | 상태 |
|---|---|---|---|
| 1 | 카테고리 상위 25개 제품 썸네일 캡처 | 사람(폰/PC) | 수동 |
| 2 | 썸네일에서 가격·용량·순위·리뷰수 추출 → 엑셀 | `analyze_thumbnails.py` | **완료** |
| 3 | 엑셀을 보고 타겟 규격·가격대 판단 | 사람 + Claude | **완료(1회차)** |
| 4 | 상세페이지에서 USP 추출 | `analyze_details.py` | 도구 완성 / **수집 지시문 발행, 결과 대기** |
| 5 | 최종 산출물(견적요청서·기획서) 출력 | `문서생성/` | **완료(견적요청서)** |

3단계를 자동화하지 않은 것은 의도적이다. 매번 카테고리 사정이 달라서
사람의 판단이 들어가야 하는 구간이다.

## 3. 폴더 구조

```
new_PD_PS/
├── README.md                     ← 이 문서
├── thumbnail_analyzer/           2단계·4단계 도구
│   ├── analyze_thumbnails.py       썸네일 → 가격/시장지표 엑셀
│   ├── analyze_details.py          상세페이지 → USP 엑셀
│   ├── requirements.txt
│   ├── README.md                   사용법
│   └── CLAUDE.md                   설계 배경 (프로젝트 메모리)
├── data/extracted/               1회차 추출 원본 (카테고리별 25건 x 6 = 150건)
├── 문서생성/                      5단계 산출물 생성기
│   ├── 견적요청서_데이터_생성.py     추출 JSON → 스펙·근거 계산
│   ├── 견적요청서_데이터.json        계산 결과 (스크립트가 만듦, 손으로 고치지 않음)
│   ├── 견적요청서_생성.js            docx 생성 스크립트
│   └── package.json
└── 신제품_생산견적요청서.docx      생성된 결과물 (공장 전달용)
```

### `data/extracted/`를 커밋해 둔 이유
엑셀(`*.xlsx`)은 `.gitignore`로 제외했지만 이 JSON은 남긴다.
**이미지를 다시 읽지 않아도 엑셀을 언제든 다시 만들 수 있는 원본**이기 때문이다.
컬럼을 추가하거나 계산식을 고쳤을 때, 재촬영 없이 `build`만 다시 돌리면 된다.

비유하자면 JSON은 **필름 원본**이고 엑셀은 **인화된 사진**이다.
인화지는 버려도 되지만 필름은 보관한다.

## 4. 처음 받았을 때 준비

```bash
# 2·4단계 도구 (파이썬)
cd thumbnail_analyzer
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 5단계 문서 생성기 (Node)
cd ../문서생성
npm install
```

**API 키는 필요 없다.** 이미지를 읽는 일은 Claude가 대화 중에 직접 하고,
파이썬 스크립트는 그 결과를 검증·계산해서 엑셀로 만드는 역할만 한다.

## 5. 견적요청서 다시 만들기

숫자는 손으로 고치지 않는다. **추출 JSON → 계산 → 문서**가 한 줄로 이어져 있다.

```bash
cd 문서생성
python3 견적요청서_데이터_생성.py   # data/extracted 를 읽어 견적요청서_데이터.json 생성
npm install                          # 처음 한 번만
node 견적요청서_생성.js              # → ../신제품_생산견적요청서.docx
```

조건을 바꾸려면 `견적요청서_데이터_생성.py` 상단의 상수만 고친다.

| 상수 | 뜻 | 현재 |
|---|---|---|
| `MARKUP` | 목표 판매가 ÷ 이 값 = 생산원가 | 3.5 |
| `TARGET_DISCOUNT` | 가격대 최저가 대비 목표 배율 | 0.95 (−5%) |
| `PLAN` | 카테고리별로 생산할 **형태** | 아래 참고 |

### 분류는 '형태'로만 한다 (중요)

본품/리필로 나누지 않는다. 본품·리필은 **브랜드가 자기 라인업 안에 붙이는 이름**이라,
인지도가 다른 브랜드끼리 1:1로 비교하면 *"리필을 본품보다 비싸게 만들자"* 는
결론이 나온다. 실제로 그런 결과가 나왔고 되돌렸다.

데이터가 말하는 사실:
- 섬유유연제 **말통 5건은 전부 본품**이고, 리필은 파우치 7건이다
- 캡슐세제는 25건 전부 본품 — **리필이라는 구분이 아예 없다** (파우치 23 / 용기 2)

즉 "말통 = 리필"은 상식일 뿐 데이터가 아니다. 형태는 브랜드와 무관한 눈에 보이는
사실이므로 비교 기준으로 쓸 수 있다.

그리고 **카테고리당 단위당 가격이 가장 싼 형태 1종만** 생산한다. 형태별로 다 만들면
비싼 형태는 가성비 제품으로 성립하지 않고, 용량이 커질수록 실현 불가능한 원가가 나온다.
나머지 형태는 기능을 차별화한 확장 품목으로 미뤄 문서 5장에 참고로만 남긴다.

카테고리별로 싼 형태가 어디인지는 다 다르다.

| 카테고리 | 채택 형태 | 그 형태의 최저 단가 |
|---|---|---|
| 세탁세제 | 용기 | 69.8원/100ml |
| 섬유유연제 | 용기 | 68.9원/100ml (리퀴드) |
| 섬유탈취제 | 용기 | 891.0원/100ml |
| 주방세제 | 말통 | 75.2원/100ml·100g |
| 살균소독제 | 말통 | 224.8원/100ml (가정용 4L) / 96.8원 (업소용 20L) |
| 캡슐세제 | 파우치 | 49.1원/개 |

## 6. 1회차 조사 결과 (2026-09 기준)

- **쿠팡 6개 카테고리 x 25개 = 150건 수집 완료**
  (세탁세제 / 캡슐세제 / 섬유유연제 / 섬유탈취제 / 주방세제 / 살균소독제)
- **단가 검산 결과: 일치 145건 · 표기없음 5건 · 불일치 0건**
  (쿠팡이 화면에 직접 표시하는 단가와 우리 계산을 대조한 것. 추가 비용 없이
  읽기 오류를 잡아내는 장치다. `표기없음`은 캡처 하단이 장바구니 바에 가려진 경우)
- 그 결과로 **7개 스펙(형태 기준. 살균소독제만 가정용·업소용 2종)의 목표 판매가·생산원가**를 도출해
  공장 전달용 견적요청서로 만들었다.

| 카테고리 | 형태 | 규격 | 목표 판매가 | 목표 생산원가 |
|---|---|---|---|---|
| 세탁세제 | 용기 | 2.5L × 4개 | 6,600원 | 1,886원 |
| 섬유유연제 | 용기 | 2.5L × 4개 | 6,500원 | 1,857원 |
| 캡슐세제 | 파우치 | 120개입 | 5,600원 | 1,600원 |
| 섬유탈취제 | 용기 | 500ml × 2개 | 8,500원 | 2,429원 |
| 주방세제 | 말통 | 13L | 9,300원 | 2,657원 |
| 살균소독제 (가정용) | 말통 | 4L | 8,500원 | 2,429원 |
| 살균소독제 (업소용) | 말통 | 20L | 18,400원 | 5,257원 |

### 목표 판매가를 정한 방식 (중요)
1. **같은 카테고리·같은 형태**의 단위당 단가를 싼 순으로 줄 세운다
2. 그중 **가장 싼 값을 그 형태의 시장 최저가로 인정한다.** 브랜드 인지도가 낮아도,
   그 형태·그 가격으로 실제 팔리고 있으면 소비자가 비교하는 기준 가격이다
3. 그 최저가에서 **약 5% 아래**를 목표가로 잡는다
4. 규격은 그 가격대 제품들이 실제로 채택한 용량·수량을 그대로 따른다

**한때 "다음 값보다 1.5배 이상 싸면 버린다"는 이상치 제외 규칙이 있었으나 폐기했다.**
섬유유연제 10L 6,890원이 시장에 없는 가격처럼 보여 넣은 규칙인데, 확인해보니
`리퀴드`라는 실재 브랜드였고 같은 브랜드가 세탁세제 10L도 팔고 있어 가격이 일관됐다.
유별나게 싼 값이 아니라 그 형태의 실제 최저가였다.

교훈: **브랜드가 미상으로 나오면 버리기 전에 추출 원본의 `notes`를 먼저 볼 것.**
이 건도 notes에 "라벨은 Laundry LiQiD"라고 적혀 있었다.

대신 최저가와 그 다음 값의 격차가 1.5배 이상이면 **문서에 그 사실을 밝힌다.**
목표가가 시장 대다수보다 한참 아래라는 뜻이므로 공장이 알아야 하는 정보다.

### 무게와 부피는 같은 선에서 비교한다
물리적으로는 g과 ml을 같은 자에 올릴 수 없지만, 생활용품 시장은 둘을 병행 표기하고
소비자도 100g당과 100ml당을 나란히 놓고 비교한다. 실제 시장의 비교 방식을 따르는 것이
목적이므로 한 무리로 본다(단가기준 라벨 `100ml·100g당`). 개수 기준(캡슐세제 1개당)은
성질이 달라 여전히 별도다.

### 한 형태 안에 쓰임이 다른 규격군이 섞이면 나눠서 각각 제안한다
살균소독제 말통에는 가정용 4L군과 업소용 19~20L군이 함께 있다. 구매자가 다른
별개 시장이므로 한쪽을 버리지 않고 2종으로 나눠 제안한다.

## 7. 반드시 지켜야 할 규칙

1. **결과물에 운영주체 회사명을 넣지 않는다.** 요청이 있을 때만 표기한다.
   문서에는 채널(쿠팡)과 카테고리로만 구분한다.
2. **상품 URL을 추측해서 만들지 않는다.** 엉뚱한 상품으로 연결되면 없느니만
   못하다. 모르면 비워두고 `검색링크` 컬럼(제품명 기반 검색 주소)을 쓴다.
3. **숫자 계산은 전부 파이썬이 한다.** AI는 이미지의 글자를 읽는 것까지만 한다.
   매출·단가처럼 돈이 걸린 값을 AI 산수에 맡기지 않기 위한 설계다.
4. **`단가기준`이 다른 행끼리 단가를 비교하지 않는다.**
   캡슐세제는 `1개당`, 액체류는 `100ml당`이라 숫자를 직접 견주면 안 된다.
5. **"만족했어요"는 구매자수가 아니다.** 쿠팡이 같은 자리에 번갈아 보여주는
   다른 문구다. 코드가 '구매'가 있을 때만 숫자로 인정하도록 막아 두었다.
6. **쿠팡은 자동 수집이 막혀 있다**(서버 IP에서 403, 약관상으로도 금지).
   캡처는 사람이 하거나, 사용자의 브라우저에서 도는 Claude 확장을 쓴다.

## 8. 알려진 제약

- **상세페이지 USP 데이터가 아직 없다.** 도구(`analyze_details.py`)는 검증까지 마쳤고,
  수집 대상(전체 150개)과 브라우저에 붙여넣을 지시문을 `targets`가 만들어 준다.
  현재 첫 테스트 묶음은 `USP분석_지시문.txt`에 있다.
  브라우저(Claude in Chrome 등)에서 받은 JSON을 `build`에 넣으면 엑셀이 나온다.
- **추정월매출은 어림값이다.** `월구매자수 x 판매가 x 2`이고, 구매자수가
  "3만명 **이상**" 같은 하한이라 실제보다 낮게 나온다.
  절대 금액이 아니라 **제품 간 규모 비교용**으로만 쓴다.
- **생성된 docx를 이 작업 환경에서 화면으로 확인할 수 없다**(오피스 변환 도구가
  깨져 있음). 구조 검사까지만 가능하므로, PDF로 내보내기 전에 Word에서
  한 번 눈으로 훑어보는 절차가 필요하다.

## 9. 다음 사람이 이어서 할 일

1. **USP 전수조사 실행** — `USP분석_지시문.txt`의 아래쪽 지시문을 브라우저(Claude in Chrome)에
   붙여넣고, 돌아온 JSON을 저장한 뒤:
   ```bash
   cd thumbnail_analyzer
   python3 analyze_details.py build --input <받은JSON> --category <카테고리> \
       --output 결과/USP.xlsx --thumbnails <썸네일엑셀>
   ```
   형식이 어긋나면 그 자리에서 어느 칸이 왜 틀렸는지 알려주고 멈춘다(엑셀을 만들지 않음).
2. 2단계 엑셀 + 4단계 USP를 합쳐 **제품기획서(docx)** 생성 (5단계 확장)
3. (선택) 대시보드 — 로컬 폴더를 열어 분석을 돌리고 결과를 보는 형태.
   브라우저는 보안상 로컬 경로를 직접 못 읽으므로, 로컬에서 도는 앱 형태가 자연스럽다.

### USP는 전수조사가 기본이다

처음에는 "질문에 필요한 제품만"으로 150개 → 13개로 좁혔는데 **이건 잘못된 판단이었다.**

USP는 가격이나 판매량과 무관하게 제품마다 다른 소구점이 존재한다. 그래서 **어느 제품에
쓸모 있는 인사이트가 있는지 미리 알 수 없다.** 저가/고가로 고르면 그 축과 상관없는
소구점을 통째로 놓친다. 순위 24위 제품의 "반려동물 피부 소독 겸용" 같은 건 가격·순위와
아무 상관이 없지만, 카테고리 확장을 생각하면 가장 값진 정보일 수 있다.

광산에서 금맥이 어디 있는지 모르면 다 파봐야 하는 것과 같다. 겉보기 좋은 곳만
골라 파면 정작 금은 다른 데 있다.

```bash
cd thumbnail_analyzer

# 1) 방식이 맞는지 작은 묶음으로 테스트
python3 analyze_details.py targets --all --batch 5 --category 세탁세제

# 2) 결과를 받아 검증·누적
python3 analyze_details.py build --input 받은.json --category 세탁세제 \
    --output 결과/USP.xlsx --thumbnails 결과/썸네일.xlsx

# 3) 이어하기 — 같은 명령을 반복하면 남은 것만 나온다
python3 analyze_details.py targets --all --batch 10 --done 결과/USP.xlsx
```

`targets`의 기본(표본 선정) 모드는 **빠른 테스트용**으로 남겨둔 것이다. 실제 수집은 `--all`.

### 이어하기가 어떻게 되는가
- 진행 상황을 별도 상태 파일에 적지 않고 **결과 엑셀에서 읽는다.** 상태 파일과 결과가
  어긋나면 무엇이 맞는지 알 수 없게 되기 때문이다
- 항목 ID는 `카테고리-파일번호`(예: `세탁세제-09`). 제품명으로는 안 된다 — 같은
  카테고리에 제품명이 똑같고 가격만 다른 옵션이 실제로 있다(스너글 섬유탈취제, 프릴 주방세제)
- 브라우저가 ID를 다르게 적으면 "대상에 없는 ID"로 알려주고, 그 항목은 남은 목록에
  그대로 둔다. 조용히 건너뛰지 않는다
- **`build`는 이어붙인다.** 같은 ID를 다시 넣으면 새 결과로 교체한다(재수집 = 수정 의도).
  기존 파일을 못 읽으면 덮어쓰지 않고 중단한다
